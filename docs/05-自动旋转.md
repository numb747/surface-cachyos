# 05 · 自动旋转

## 链路

```
加速计（/sys/bus/iio/devices/iio:device0）
   │
   ▼
iio-sensor-proxy          ← 把原始数据暴露到【系统】D-Bus
   │  net.hadess.SensorProxy
   ▼
iio-hyprland              ← 【普通用户】进程，调 hyprctl 转屏幕
   │
   ▼
Hyprland 的 monitor transform
```

## 为什么用 systemd user unit 而不是 exec_cmd

直接 `hl.exec_cmd("iio-hyprland")` 能用，但有个**偶发问题**：
开机后不旋转，重启一次又好了。

原因：`iio-hyprland` 是普通用户进程，靠 D-Bus 读 `net.hadess.SensorProxy`。
光装上 `iio-sensor-proxy` **不保证**它在 `iio-hyprland` 启动时已经就绪 ——
这东西由 D-Bus 按需激活。

这种偶发最难查，因为没有稳定复现路径。用 unit 声明依赖，
让 systemd 保证顺序：

```ini
[Unit]
After=graphical-session.target
Wants=iio-sensor-proxy.service
PartOf=graphical-session.target

[Service]
Environment=DBUS_SESSION_BUS_ADDRESS=unix:path=%t/bus
ExecStart=/usr/bin/iio-hyprland
```

> ⚠ 用 `Wants=` 而不是 `Requires=`：`iio-sensor-proxy.service` 是 `static`
> （没有 `[Install]` 段），由 D-Bus 激活。写 `Requires=` 会让本 unit
> 在它没被激活时**直接失败**，反而更糟。

## 装法（要 sudo，自己跑）

```bash
sudo install -m644 systemd/etc/iio-hyprland.service \
     /etc/systemd/user/iio-hyprland.service
systemctl --user daemon-reload
systemctl --user enable --now iio-hyprland.service
```

> `./install.sh sensor` 只打印这两条命令，不代跑。

## 验证

```bash
# 1. 传感器在不在 D-Bus 上
busctl --system list | grep net.hadess.SensorProxy

# 2. 实时看传感器读数（转动机器应该看到值变化）
monitor-sensor

# 3. 服务状态
systemctl --user status iio-hyprland.service

# 4. 屏幕当前朝向
hyprctl monitors | grep -E 'transform|Monitor'
```

`transform` 的值：正常 `0`，顺时针 90° 是 `1`，180° 是 `2`，270° 是 `3`。

## 失效时怎么查

**症状：完全不旋转**

按上面 1→4 的顺序查。最可能是 `busctl` 那步没输出 ——
说明 `iio-sensor-proxy` 没起来，或者它没检测到加速计。

检查传感器是否真的存在：

```bash
ls /sys/bus/iio/devices/
cat /sys/bus/iio/devices/iio:device0/name    # 应含 accel
```

**症状：偶尔不旋转**

就是上面那个启动顺序问题。确认 `iio-hyprland` 是从 systemd 起的，
而不是从 `autostart.lua` 的 `exec_cmd`：

```bash
systemctl --user status iio-hyprland | head -3
```

如果 unit 是 inactive 而进程却在跑，说明有两处在拉它，
删掉 `autostart.lua` 里的 `hl.exec_cmd("iio-hyprland")` 那行。

**症状：转的方向反了**

`iio-hyprland` 的默认假设不适用于所有机型。这个要改它的源码或提 issue，
不是配置能解决的。Surface Pro 6 上默认是对的。

## 其它传感器

`iio-sensor-proxy` 除了加速计，还会暴露环境光传感器（`net.hadess.SensorProxy.AmbientLightLevel`）。
没配自动亮度，因为 Surface 的背光在 Linux 下控制得不好，
而且平板模式下亮度基本靠手动。想接的话监听 D-Bus 属性变化调 `brightnessctl` 即可。
