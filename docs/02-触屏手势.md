# 02 · 触屏手势

配置文件：`config/hypr/touch.lua`。

## 为什么需要插件

**Hyprland 原生不支持用触屏拖动窗口。** 不是配置没写对，是架构上没有这条路：

| | 触屏 | 鼠标 |
|---|---|---|
| 事件来源 | `ITouch` | `IPointer` |
| 回调 | `onTouchDown/Move/Up` | `onMouseButton` |

两条**完全独立**的路径。所以主仓 `binds.lua` 里的
`mainMod + mouse:272 → window.drag()` 对手指无效 —— 手指根本不产生按键事件。

原生唯一支持的触屏动作是 `gestures:workspace_swipe_touch`（滑切工作区），
这个不需要插件，`touch.lua` 顶部就开了。

其余手势靠 **hyprgrass**。

## 已配的手势

| 手势 | 动作 |
|---|---|
| 三指长按 400ms | 拖动窗口 |
| 四指长按 | 调整窗口大小 |
| 三指点击 | 切换浮动/平铺 |
| 底部边缘上滑 | 关闭当前窗口 |
| 底部边缘下滑 | 显示/隐藏虚拟键盘 |
| 单指横向滑 | 切换工作区（原生） |

## 两个关键点

### 1. `hl.plugin` 命名空间只有在插件加载后才存在

所以插件相关调用**必须**包在守卫里：

```lua
if hl.plugin.hyprgrass == nil then
    return
end
```

不包的话，插件没装（或 ABI 失效被跳过）时整份配置会报错。
注意 `hl.plugin` 这个**表**总是存在的（即使一个插件都没有），
所以要判的是 `hl.plugin.hyprgrass` 是不是 nil —— 实测过。

### 2. `mouse = true` 是拖动能不能用的关键

```lua
hl.plugin.hyprgrass.bind {
    pattern = { kind = "longpress", fingers = 3 },
    action  = hl.dsp.window.drag(),
    mouse   = true,          -- ★ 没有这行就拖动不了
}
```

它的作用是把触屏手势**翻译成鼠标拖拽事件**，塞进上面说的 `IPointer` 通道。
不加的话手势能被识别，但不会传成拖动。

## 调参

```lua
sensitivity      = 4.0,   -- 默认 1.0 在平板屏幕上太钝，作者建议 4.0
long_press_delay = 400,   -- 长按判定毫秒数。嫌拖窗口要按太久就调小
edge_margin      = 10,    -- 距边缘几像素算"边缘"
```

改完 `hyprctl reload` 即可，不用重启。

**验证配置真的生效了**：

```bash
hyprctl getoption plugin:hyprgrass:sensitivity
```

应返回 `4.0`。返回 `1.0` 说明 `touch.lua` 没被 require —— 去跑 `./install.sh hook`。

## 关于插件日志

`hyprgrass` 的手势绑定日志走 `LOG(Log::DEBUG, …)`，**需要 Hyprland 以 `-v` 启动
才看得到**。所以平时日志里没有手势信息是正常的，不代表没注册。

想确认绑定注册了，别去翻日志，改配置值然后看 `hyprctl getoption` —— 能读到
非默认值就说明"插件加载了 + 配置在插件加载后被重新解析了"，这比读日志可靠。

## 排查过的替代桌面

都试过，都留在 Hyprland 更好：

| 桌面 | 为什么不换 |
|---|---|
| GNOME 50 | mutter 的触屏拖标题栏会**冻结整个 shell**。没键盘时只能强关电源 |
| KDE Plasma 6.7 | maliit 虚拟键盘是 Qt5 构建、英文 only |
| niri 26.04 | Mod+拖拽能用，但 OSK 要自己配，等于换了个地方解决同样的问题 |

GNOME 那个冻结是决定性的：这正是"没键盘时触屏是最重要输入手段"的场景，
而它会在最需要的时候锁死。
