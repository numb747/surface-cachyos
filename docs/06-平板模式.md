# 06 · 平板模式

平板模式 = 摘掉 Type Cover 之后的工作形态。不引入常驻 UI，**全部走手势**。

---

## 一、手势表

**设计前提（先读这段，否则下表看起来会很保守）**

这台机器的触摸有两个实测特性，直接决定了手势怎么设计：

| 实测 | 数据 | 后果 |
|---|---|---|
| **按住不动很稳** | 三指按住 5 秒 → 连续 3.4 秒不断 | tap / longpress 可靠 |
| **快速移动会断触** | 一次横划被拆成 9–16 段，每段 8–60ms | swipe 不可靠 |

所以**只用点击和长按，不用滑动**。断触的实测数据与排除过程见
[`08-触摸断触.md`](08-触摸断触.md)。

**第二条硬规则：不做破坏性动作。** 触屏误触的代价远大于它省下的那一次点击：

| 动作 | 误触的后果 | 结论 |
|---|---|---|
| 关窗口 | 丢工作 | 不绑 |
| 移动窗口到别的工作区 | 窗口"不见了"，纯触摸难找回 | 不绑 |
| 切换抽屉工作区（special） | 空工作区盖住屏幕、**不自动恢复**，看着像窗口凭空消失 | 不绑 |

这三条都是旧版配置里绑过、并且实际造成过事故的（2026-09-26：五指下滑被误触
打开抽屉工作区，屏幕只剩壁纸，用户以为窗口被关了）。

### 手势总表

| 手势 | 动作 |
|---|---|
| 三指点击 | 启动器（应用 + 窗口搜索） |
| 三指长按 | 拖动窗口 |
| 四指点击 | 全屏 |
| 四指长按 | 控制中心 |
| 五指点击 | 剪贴板 |
| 底部边缘下滑 | 虚拟键盘 |
| **双指长按** | **救援 —— 复位界面** |
| 五指长按 | 退出平板模式 |

指头数分配在两个文件之间不能重复，否则谁生效取决于插件内部顺序：

- `config/touch.lua`：3 指点击/长按、4 指点击/长按、5 指点击
- `config/touch-tablet.lua`：2 指长按（救援）、5 指长按（退出平板）

### 键盘等价物

接上 Type Cover 时用键盘更快，两个入口并存。见 `mykeys.lua` 第 3、4、5 节。

### 手势没覆盖的：用虚拟键盘按 PC 键位

关窗口、新桌面这类动作按规则不绑手势（见上）。平板上的办法是
**底部边缘下滑呼出虚拟键盘，点 `Alt`，再点字母**。wvkbd 的 Ctr/Sup/Alt
是粘滞键，点一下锁住、作用于下一个键，不用两指同按。

| 键位 | 动作 |
|---|---|
| `ALT + W` | 关窗口 |
| `ALT + T` | 跳到一个空工作区（新桌面） |
| `ALT + Return` | 切换全屏（与四指点击相同） |
| `ALT + M` | 切换平板 / PC 模式 |

这四个在 `mykeys.lua` 第 6 节，**两个模式都生效**，接着 Type Cover 时直接按。
每个动作之后都会顺手收起虚拟键盘 —— wvkbd 自己没有"收起"键
（左下角 ⌨ 是切布局）。

关窗口放在这里不违反第二条硬规则：那条防的是手势误触，而这里要连点
两个指定的键，误触概率可以忽略。

2026-09-27 真机实测（uinput 合成触摸去点 wvkbd）：四个键位都触发，
组合键被 Hyprland 接住、不会漏给应用，按完键盘收起；`ALT + M` 连切 4 次全部正确。

**两个坑：**

- **wvkbd 的 `Caps` 开着时，所有快捷键都不响应。** 连 uinput 模拟的物理键盘
  也一样。"点了没反应"先看 Caps。
- **Firefox 会把单独的 Alt 当成"弹出菜单栏"。** 组合键被 Hyprland 接走后，
  Firefox 只看到一次单独的 Alt。本机 `user.js` 已加
  `ui.key.menuAccessKeyFocuses = false`（重启 Firefox 生效）。
  其他带菜单栏的应用可能有同样的现象，菜单栏再点一下别处就会消失。

未测：焦点在文本框、rime 正在输入时，组合键会不会先被输入法吃掉。

### 常见操作速查（平板模式）

可收藏的网页版：`docs/cheatsheet.html`，由 `./install.sh tablet` 装到
`~/.local/share/surface-cachyos/cheatsheet.html`。改手势/键位时两处一起改。

| 想做什么 | 怎么做 |
|---|---|
| 切到 PC 模式 | 五指长按，或 `ALT + M` |
| 切到平板模式 | 拔 Type Cover，或 `ALT + M` |
| 新建桌面 | `ALT + T` |
| 切换桌面 | 点顶栏中间的工作区圆点，或三指点击打开启动器搜窗口 |
| 全屏 / 退出全屏 | 四指点击 |
| 关掉当前应用 | `ALT + W` |

### 顶栏按钮（看视频 / 小说用）

顶栏右侧三个图标（`config/noctalia/config.toml` 的 `[widget.osk]` 等，动作在
`tablet/surface-ctl`）。noctalia 里手指长按 = 右键，所以"长按"是次要动作：

| 图标 | 点 | 长按 |
|---|---|---|
| ⌨ 键盘 | 显示 / 隐藏虚拟键盘 | 隐藏 |
| ⟳ 旋转 | 锁定 / 解锁自动旋转 | 侧边音量键 ⇄ 翻页键 |
| 🔒 锁屏 | 锁屏（平板模式下自动弹键盘） | 电源菜单 |

- **旋转锁** = 停 / 启 `iio-hyprland` 用户服务。服务是 enable 的，重启后自动恢复旋转。
  只在平板模式下有用：PC 模式固定横屏，点了只弹提示（见下"模式与屏幕方向"）。
- **翻页键**：标记文件 `$XDG_RUNTIME_DIR/surface-page-keys`，`mykeys.lua` §7 的音量键
  每次按下时查它，有就给当前窗口发 `PageDown` / `PageUp`（音量− 下一页）。
  重启即清空。锁屏时、没有窗口时照常调音量。实测：开启后按音量键，窗口收到
  `Next` / `Prior`，音量不变；关闭后恢复调音量。

### 空闲熄屏

`[idle.behavior.screen-off]`：5 分钟不碰熄屏，碰一下亮。**不自动锁屏**（平板上
每次输密码不值得）。熄屏前 `surface-ctl idle-screen-off` 查 `pactl` 有没有未暂停的
音频流，有就跳过 —— Firefox 放视频**不**向合成器申请防熄屏（实测播放抖音时
`inhibitingIdle = false`），不查的话一动不动看长视频会被熄屏。

### 触屏地图

`docs/touchmap.html`（装到 `~/.local/share/surface-cachyos/touchmap.html`）：
到处划，走过的地方涂绿、断开处标红，攒多了就是这块屏的死区图。
断开判定与 `docs/08` 分析用的一致：抬起后 150ms 内、60px 内又落下。
结果按横 / 竖屏分开存在浏览器 localStorage 里。

### 怎么看出当前是什么模式

| 标识 | 平板模式 | PC 模式 |
|---|---|---|
| 窗口边框 | **橙色**，3px | 绿色，2px（CachyOS 默认） |
| 屏幕方向 | 跟着传感器转 | 固定横屏 |
| 切换那一刻 | 右上角通知"平板模式" | 右上角通知"PC 模式" |

- 边框写在 `touch-tablet.lua` 里 —— 这个文件只在平板模式下加载，所以颜色和
  手势集是同一个开关，不会对不上。
- 通知由 `tablet-mode` 在真的切换时弹，插拔、`ALT + M`、五指长按都经过它。
- **顶栏做不了随模式变化的图标**：noctalia v5 的 `custom_button` 图标和文字都是
  静态的（v4 有动态标签，v5 没了，上游 issue #4570）。要做只能写 noctalia 插件，
  不值得。

### 模式与屏幕方向

**PC 模式固定横屏、不自动旋转；平板模式自动旋转。**接着 Type Cover 物理上只能
横着用，所以 PC 模式下转屏只有坏处。

实现分三处，缺一不可：

1. `monitors.lua` 的基线方向按模式取（`TABLET_MODE`，`variables.lua` 读标记文件）：
   PC 0、平板 3。切模式就是 reload，reload 读到的基线就是对的。
2. `iio-hyprland.service` 带 `ConditionPathExists=%S/surface-config/tablet.flag`，
   PC 模式下谁来 start 都起不来（graphical-session、autostart、顶栏按钮）。
3. `tablet-mode on` 起旋转服务后**自己读传感器转一次**（`busctl` 读
   `AccelerometerOrientation`），再交给 iio-hyprland 监听后续变化。

**踩过的坑（2026-09-27）：** 早先基线写死竖屏 3，于是**插上 Cover 回 PC 模式，
屏幕反而变竖屏**。iio-hyprland 只在方向**变化**时转，平板不动就一直竖着。它源码里
虽有启动时主动读一次的 `init_orientation`，本机上实测不生效（设成竖屏后重启它 3 次
都没转回来），所以第 3 条不能省。

**排查时的干扰项：** 熄屏（DPMS off）时屏幕的 transform 延后到亮屏才生效，
触摸的立即生效。熄屏期间 `hyprctl` 查到"屏幕 3 / 触摸 0"是正常的，亮屏就一致。

## 二、救援手势（双指长按）

**这是本配置最重要的一条**，旧版没有。

平板模式下没有键盘，够不着 `SUPER+1`。一旦手势误触把界面切到空工作区、
或者卡在半截的滑动动画里，纯触摸用户**没有任何办法回来**。

`tablet-rescue` 做的事，**必须幂等** —— 状态正常时跑一次什么都不改：

1. 困在抽屉里的窗口 → 移回工作区 1
2. 抽屉工作区开着 → 关掉（必须在搬完窗口**之后**，见下）
3. 当前工作区是空的 → 跳到窗口最多的那个

### 踩过的坑：救援键自己变成事故源

第一版无条件调 `toggle_special()`。**抽屉没开时这个调用会打开一个空抽屉**，
盖住整个屏幕 —— 救援键成了事故源。实测日志：

```
[18:07:02] --- rescue 开始 ---
[18:07:02] toggle_special 已调用     ← 抽屉本来没开，这一下打开了
```

用户每按一次双指长按，屏幕就被一个空抽屉盖住一次。

修法是**先查状态再动手**，而且关抽屉要复查 —— 从抽屉里搬走窗口后
Hyprland 会**稍后重新显示**抽屉（实测：关完立刻查是关的，0.5 秒后又开了），
所以关的动作要循环确认。

键盘等价物：`SUPER + SHIFT + Escape`。

## 三、切换机制

`tablet-mode` 维护一个标记文件：

```
~/.local/state/surface-config/tablet.flag
```

`config/touch.lua` 在**配置加载时** `io.open` 这个文件，存在就
`require("config.touch-tablet")`。

```bash
tablet-mode on       # 进平板模式
tablet-mode off      # 回 PC 模式
tablet-mode toggle
tablet-mode status
tablet-mode auto     # 按 Type Cover 在不在自动判定（Cover 插拔、开机时用这个）
```

### 为什么用标记文件而不是运行时 API

`hyprctl keyword` 对 Lua 配置**不可用**：

```
keyword can't work with non-legacy parsers. Use eval.
```

而且实测 `hyprctl repl` **只校验参数、不真派发** —— 从 repl 里调
`hl.dsp.exec_cmd("touch /tmp/probe")` 会返回成功，但 `/tmp/probe` 从未出现。
所以"运行时动态 bind/unbind 手势"这条路是假的。

标记文件 + `hyprctl reload` 是唯一可靠的状态传递方式。

### Type Cover 怎么检测

按 **USB VID/PID**（`045e:09c0`）在 `/sys/bus/usb/devices/` 里搜，不按端口路径。

旧版硬编码端口 `1-7`，换机型/换键盘就会失效。搜 VID/PID 更稳，
但仍然**不能**写成"任何键盘出现就切" —— 那会让外接 USB 键盘误触发。

### 插拔怎么触发切换

```
udev 规则（70-surface-tablet-mode.rules）
  └ 给 Cover 打 systemd 标签 + 别名 /dev/typecover，不跑命令
      → 用户管理器里出现 dev-typecover.device
      → SYSTEMD_USER_WANTS 拉起用户单元 surface-typecover.service
          ExecStart = tablet-mode auto        （接上）
      拔掉 → 设备单元消失 → BindsTo 停掉该单元
          ExecStop  = tablet-mode auto        （拔掉）
开机：Hyprland 启动时跑一次 tablet-mode auto（autostart.lua）
```

`tablet-mode auto` 每次都重新看 Cover 在不在，不看是哪个事件叫它的，
所以重复触发、乱序都不会切错。

**踩过的坑：旧版 udev 规则从来没工作过。** 旧规则是
`RUN+="systemd-run --user ... tablet-mode auto"`。RUN 以 root 跑，
`systemd-run --user` 连的是 **root 自己的**用户管理器 —— 不存在，于是 exit 1。
就算连上了，`$HOME` 也是 `/root`，标记文件写错地方，`hyprctl` 也找不到
Hyprland 实例。2026-09-27 翻日志：3 天 15 次触发全部失败，那段时间的
模式切换其实全靠手动 `ALT + M`。doctor 只查规则文件在不在，所以一直报绿；
现在它比对规则内容，并检查 Cover 接着时 `surface-typecover.service` 在跑。

## 四、已知风险

1. **外接 USB 键盘会误判。** 如果你接一个普通 USB 键盘，`tablet-mode auto`
   不会切换（它只认那个 VID/PID），所以形态判断仍以 Type Cover 为准。
2. **换机型/换键盘时要改 VID/PID。** 默认 `045e:09c0` 是 Surface Pro 6 的
   Type Cover。可用 `SURFACE_COVER_VID` / `SURFACE_COVER_PID` 覆盖。
3. **休眠恢复后状态可能错乱。** 兜底是五指长按切回 PC 模式，
   或者 `tablet-mode toggle`。

## 五、音量、亮度、开关屏保持物理键

Surface 侧边有**实体音量键**。这是唯一一类"物理键优于触摸"的操作 ——
盲操、不占屏幕、不需要看。亮度键在 Type Cover 上。

手势里**不做**音量/亮度（旧版也没做，这里只是记下为什么）。
