# 03 · 虚拟键盘

## 问题的形状

目标：点输入框自动弹键盘，点到别处自动收，不用物理键。

看起来该用 `wvkbd --auto`。**但它不行**，原因是一个协议冲突：

```
fcitx5  ──占用──▶  zwp_input_method_manager_v2
wvkbd --auto  ──要绑定──▶  zwp_input_method_manager_v2
                            ↑ 已经被占了
```

fcitx5 跑着 rime 打中文，而它作为 Wayland 输入法**必须**占用
`zwp_input_method_v2`（这就是输入法的定义）。`wvkbd --auto` 也想绑这个协议来自动显隐，
于是两者互斥：

- 让 fcitx5 让出协议 → **中文输入没了**
- 让 wvkbd 放弃 `--auto` → **键盘不自动弹**

当时试过 squeekboard，同样是这个问题，它也是走 `input-method-v2` 的。

## 解法：反过来，让 fcitx5 通知键盘

关键观察：**fcitx5 本来就知道焦点在哪**。它接管了 `zwp_text_input_v3`
的输入上下文，文本框获得/失去焦点它第一个知道。

所以要的不是"键盘自己感知焦点"，而是"**fcitx5 感知焦点后去通知键盘**"。

这就是 `fcitx-virtualkeyboard-adapter` —— hyprgrass 同作者的配套项目，
一个 fcitx5 插件，监听 `InputContextInputMethodActivated` / `Deactivated`
事件，然后执行你配置的命令（带 400ms 防抖）。

而 wvkbd 这边，只要**不用 `--auto`**，它就走 `zwp_virtual_keyboard_v1` 发按键 ——
**那个协议和 fcitx5 不冲突**，因为它是"假装成物理键盘"，不是"当输入法"。

于是链路变成：

```
点输入框
  → fcitx5 收到 text-input-v3 的 activate
  → 适配器执行 ActivateCmd
  → wvkbd-toggle show
  → wvkbd 显示（同时它继续用 virtual-keyboard-v1 发按键给 fcitx5 处理）
```

两边各司其职，协议不撞。

## 三个部件

| 部件 | 位置 | 作用 |
|---|---|---|
| `wvkbd-deskintl` | AUR 包 | 键盘本体，桌面布局 |
| `wvkbd-toggle` | `~/.local/bin/` | 把 wvkbd 的信号接口包成 show/hide/toggle |
| `libvirtualkeyboardadapter.so` | `/usr/lib/fcitx5/` | fcitx5 插件，焦点变化时调上面那个脚本 |

### wvkbd 的信号接口

wvkbd 用信号控制可见性，没有别的接口：

```
SIGUSR1  = 隐藏
SIGUSR2  = 显示
SIGRTMIN = 切换    （kill -34）
```

`wvkbd-toggle` 就是把这套包起来，并且处理"没运行就启动"的情况。

### 适配器要从源码编译

AUR 里**没有**这个包，只能自己编：

```bash
git clone https://github.com/horriblename/fcitx-virtualkeyboard-adapter
cd fcitx-virtualkeyboard-adapter
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
sudo cmake --install build      # ← 自己跑
```

装两个文件：
- `/usr/lib/fcitx5/libvirtualkeyboardadapter.so`
- `/usr/share/fcitx5/addon/virtualkeyboardadapter.conf`

然后重启 fcitx5：

```bash
fcitx5-remote -r 2>/dev/null; pkill fcitx5; sleep 1; fcitx5 -d
```

> 它跟 fcitx5 自带的 `libvirtualkeyboard.so`（DBus 后端）**名字不同，不冲突**。

### ⚠ 配置里必须用绝对路径

这是实测踩到的坑。适配器内部是 `system()` 执行命令，而 **`system()` 的 PATH
继承自 fcitx5 进程**，fcitx5 的 PATH 长这样：

```
/usr/local/sbin:/usr/local/bin:/usr/bin:/usr/bin/site_perl:…
```

**没有 `~/.local/bin`。** 所以写

```ini
ActivateCmd="wvkbd-toggle show"        # ✗ 静默失败
ActivateCmd="/home/charlen/.local/bin/wvkbd-toggle show"   # ✓
```

配置在 `fcitx5/conf/virtualkeyboardadapter.conf`。改完 `fcitx5-remote -r` 重载，
不用重装。

## 只在平板模式下显示

`wvkbd-toggle` 的 `show` / `toggle` 会先看平板标记文件
（`~/.local/state/surface-config/tablet.flag`），**PC 模式下什么都不做**，`hide` 照常。
四个调用方（fcitx 适配器、底部边缘手势、`SUPER+K`、`mykeys.lua` §6）都经过它，
所以判断只写在这一处。`tablet-mode off` 切回 PC 时顺手收起键盘。

以前 PC 模式下也会弹，是因为 fcitx 适配器只管"文本框有没有焦点"、不知道有没有物理键盘。

## wvkbd 卡死：键盘"消失"（2026-09-27）

**现象**：平板模式下键盘突然再也叫不出来，点输入框、边缘手势、`SUPER+K` 全无反应。
进程还在，只是不再响应信号。

**原因**：wvkbd 0.19.4（当时的 AUR 版，上游 master 也一样）的主循环是

```c
poll(fds, 2, -1);                       // 同时等 wayland fd 和信号 fd
if (wayland 可读) wl_display_dispatch(display);
```

`wl_display_dispatch()` 会一直阻塞到默认队列上有事件为止。如果刚读到的只有
`delete_id` 或发给**已销毁对象**的事件（show 之后 configure 还没到就 hide 了），
它就回去单独 poll wayland fd、再也不返回 —— 信号 fd 没人看了，此后所有
show/hide 都石沉大海。

实测：内核里 SIGUSR1/SIGUSR2/SIGRTMIN 全部挂在待处理队列上；gdb 栈停在
`main → wl_display_dispatch_queue → ppoll`；`WAYLAND_DEBUG` 最后一行是
`discarded [unknown]#40.[event 0]`。间隔 10–20ms 连发 show/hide，每 3–4 轮能复现一次。
fcitx 焦点抖动（输入框频繁获得/失去焦点）就会产生这种连发。

**对策**（在 `wvkbd-toggle` 里，没改 wvkbd 本身）：

1. 不再用 SIGRTMIN 盲切，先用 `hyprctl layers` 查键盘在不在屏幕上；
2. 发完信号**核对结果**，0.6 秒内 layer 没按预期出现/消失 → 判定卡死，`kill -9` 后重开；
3. `flock` 把并发调用排队，减少连发。锁的 fd 不能让 wvkbd 继承（`9>&-`），
   否则它常驻期间一直持锁，之后的调用全部排不上队 —— 实测踩过。

真修法是把主循环改成 `wl_display_prepare_read` / `read_events` / `dispatch_pending`，
poll 就始终同时覆盖两个 fd。补丁写过、没装：这里的自愈已经够用，不值得多维护一个包。

## 登录界面（greetd）没有虚拟键盘

开机停在密码框时虚拟键盘弹不出来，这是**结构性的**，改 wvkbd-toggle 解决不了：

- greetd 用的是 `noctalia-greeter` 自带的 wlroots 小合成器，**只提供** compositor /
  xdg-shell / seat 这几个协议（`nm -D` 查过），**没有** layer-shell 和
  virtual-keyboard —— wvkbd 连窗口都建不出来；
- 那个会话在 `greeter` 用户下跑、在 Hyprland 之前，Hyprland 的手势、fcitx、wvkbd 都还没起来。

**解法：开机自动登录**（greetd 的 `initial_session`，配置在 `setup/greetd/config.toml`，
装法见 `./install.sh system` 第 6 条）。只在本次开机第一次生效；注销或 Hyprland 崩溃后
回到原登录界面、要输密码，不会循环。代价是开机不要密码。

进桌面之后的**锁屏**（noctalia 的 session lock）是另一回事：键盘也盖不上去，
因为 Hyprland 锁屏时只渲染锁屏界面。本机没有配置空闲自动锁屏，只有手动锁 / 锁并睡眠会锁。

## 兜底：手动切换

自动显隐有时会猜错（想在没焦点的地方打字），所以保留手动途径：

| 方式 | 绑定 |
|---|---|
| `SUPER + K` | 切换 |
| `SUPER + SHIFT + K` | 强制显示 |
| 底部边缘下滑 | 切换（纯平板模式下用这个，够不着键盘） |

这些在 `config/touch.lua` 和主仓的 `binds.lua` 里。

### 用它按快捷键

wvkbd 的 Ctr/Sup/Alt 是粘滞键，发出去的组合键能触发 Hyprland 的 bind
（2026-09-27 实测）。平板上的关窗口、新桌面等动作就靠这个，
键位表和两个坑（Caps 开着时全部失效、Firefox 单 Alt 弹菜单栏）见
[`06-平板模式.md`](06-平板模式.md) 的"用虚拟键盘按 PC 键位"。

`wvkbd-toggle` 也可以直接命令行用：

```bash
wvkbd-toggle          # 切换（没运行就启动）
wvkbd-toggle show     # 强制显示
wvkbd-toggle hide     # 强制隐藏
```

## 键盘高度

`wvkbd-toggle` 里的 `HEIGHT` 默认 300px。本机屏幕是 2736×1824 @ scale 2 →
逻辑分辨率 1368×912，键盘占 300px 比较合适。想改：

```bash
WVKBD_HEIGHT=360 wvkbd-toggle
```

或改脚本里的默认值。
