# 00 · 背景 —— 为什么要有第二个仓

## 问题的形状

主仓 `numb747/cachyOS-config` 是给**纯 PC** 用的：源机 `david` 是 2560×1440 的 27" 显示器，
笔记本 `monkey` 是 1920×1080 的普通翻盖机。两台都有**物理键盘**、都**不触屏**、
都**不旋转**。

本机（`charlen`，Surface Pro 6）跟它们差得比"多几个配置文件"更根本：

| | 主仓那两台 | 这台 Surface |
|---|---|---|
| 输入 | 物理键盘 + 触控板 | 触屏为主（原话："我很多时候是真的只用来做平板"） |
| 屏幕 | 固定朝向 | 会转（加速计） |
| 内核 | 官方内核 | `linux-surface`（IPTS 触屏驱动不在主线） |
| 虚拟键盘 | 不需要 | 刚需 |
| 窗口拖动 | 鼠标拖标题栏 | 触屏长按拖（Hyprland 原生不支持） |

硬件差异那一列**不是配置取舍，是能力有无**。硬塞进主仓会有两个后果：
主仓的读者以为那是通用做法；本机一同步就把适配层冲掉。

## 两条原则

**1. 主仓继续"远程永远赢"。**
这条不动。本机照旧 `sync.sh --pull` 对齐，该有的永久差异（`eDP-1`、路径）也照旧。
适配层不参与那套同步 —— 它有自己的仓。

**2. 适配层不"拥有"主仓的文件，只往里注入挂钩。**
这是本仓最关键的设计约束，也是它跟主仓最不一样的地方。

`~/.config/hypr/hyprland.lua` 和 `config/autostart.lua` 归主仓管。
下一次 `--pull` 会把它们覆盖回远程版本，本仓写进去的东西就没了。

处理办法不是"别覆盖"（那等于放弃同步），而是：

> **覆盖会发生，所以我们每次覆盖之后重新注入。**

具体是 `install.sh` 的 `hook` 模块 —— 它把 `require("config.touch")`
和 `hl.exec_cmd("iio-hyprland")` 重新插回去，用 BEGIN/END 标记块保证幂等
（重复跑不叠加）。`doctor.sh` 负责告诉你"挂钩还在不在"。

所以本仓的日常动作是：**同步完主仓，跑一次 `./install.sh hook`。**

## 为什么不合并成一个仓

想过。三个理由否掉了：

1. **主仓有别的消费者。** `david` 是源机，包从那儿打出来。往里塞 Surface 专属的
   内核配置和触屏手势，等于让源机也带着一堆用不上的东西。
2. **主仓的 `install.sh` 不碰系统。** 它明说"只写 $HOME 下的文件，不需要 sudo"。
   而 Surface 适配必须装内核、装 udev/iptsd、往 `/etc` 写 systemd unit —— 全要 sudo。
   混在一起会破坏那条性质。
3. **失效模式不同。** 主仓坏了是"配置不对"，本仓坏了是"触屏不能用"。
   分开之后 `doctor.sh` 能专测硬件链路，而不是在一堆主题/终端配置里捞。

## 跟主仓的关系图

```
~/cachyOS-config  (numb747/cachyOS-config)   ← 远程永远赢
    │  管：hyprland.lua、autostart.lua、binds.lua、mykeys.lua…
    │
    │  sync.sh --pull 覆盖
    ▼
~/.config/hypr/…
    ▲
    │  注入挂钩（可被覆盖，覆盖后重跑 install.sh hook）
    │
~/surface-config  (numb747/surface-config)   ← 本仓
       管：touch.lua、wvkbd-toggle、适配器配置、iio-hyprland unit
       + hyprgrass 插件、linux-surface 内核、iptsd
```

两边都往 `~/.config/hypr/` 写字，但**写的不是同一批文件**：
主仓写 `hyprland.lua`（入口）和 `autostart.lua`，本仓写 `config/touch.lua`（新文件，
主仓不认识它）。唯一重叠的是"往主仓的文件里插一行"，这正是 `hook` 模块要处理的。
