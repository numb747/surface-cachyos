# 04 · 坑

按踩到的顺序记。每条都是实测过的，不是推测。

## 1. hyprpm 会清 sudo 时间戳，且不能用管道喂 stdin

**最坑的一条。** 花了半个多小时才定位。

源码在 `hyprpm/src/helpers/Sys.cpp`：

```cpp
// 每个需要 root 的子命令
NSys::root::cacheSudo();                              // sudo echo hyprland
CScopeGuard x([] { NSys::root::dropSudo(); });        // sudo -k
```

`dropSudo()` 跑的是 `sudo -k`，**作废整个 sudo 时间戳**。
所以每条 hyprpm 命令都会重新问密码 —— 这是**正常现象，不是故障**。

**致命组合**：`yes | hyprpm add …`

管道顶替了 stdin，`cacheSudo()` 需要密码时拿不到输入，
`pam_unix(sudo:auth)` 报 `conversation failed`。而 hyprpm 打印的是：

```
[ERR] ✖ Failed to write plugin state
```

这个信息**完全误导** —— 真正挂在 `DataState.cpp:122` 的 `sudo install` 那一步。

**同理 `sudo -n true` 后台保活也没用**：`-n` 绝不提示密码，时间戳被清掉后无法重建。

**正确做法**：真终端里逐条手敲，`Are you sure? [Y/n]` 敲 `y`，要密码时手输。

**顺序要求**：全新状态下 `hyprpm update` 必须在前。否则 `add` 会因为
`main.cpp:115` 的 `Headers outdated, please run hyprpm update.` 直接返回 1。

## 2. 不要用 AUR 的 hyprgrass-git

AUR 包停在 2025-08，而本机 Hyprland 是 0.56.2。

当时我**先看 AUR 的日期就下了结论**说"插件错过了一年的 ABI"，这是错的。
去克隆上游才发现最新提交是 2026-09-25，且 `hyprpm.toml:66` 里 pin 的
commit 正是本机在跑的那个：

```toml
["efb50993780079460b0cbed1363e2166a2de1d9f", "8e605468…"] # v0.56.2
```

**教训：AUR 包的日期只说明打包者多久没更新，不说明上游状态。**
判断兼容性要看上游。

## 3. hyprgrass-backlight / hyprgrass-pulse 编译失败是正常的

`hyprpm add` 的输出里这两个会报错。**不是故障** ——
上游把它们的 build 步骤换成了 `echo 1`（清单里标了 deprecated，
功能移到了 `extras/` 的 Lua 模块）。

只有 `hyprgrass` 本体需要编译成功。

## 4. 插件加载 ≠ 配置生效

`hyprctl plugin list` 里有 hyprgrass，**不代表** `touch.lua` 被读进去了。

`touch.lua` 靠 `hyprland.lua` 里的一行 `require("config.touch")` 拉起来，
而那行是注入的 —— 主仓 `sync.sh --pull` 会把它冲掉。

**验证方法**：

```bash
hyprctl getoption plugin:hyprgrass:sensitivity     # 应为 4.0，不是默认 1.0
```

能读到非默认值，说明"插件加载了 **且** 配置在插件加载后被重新解析了"。

（试过用 `hyprctl eval 'hl.plugin.hyprgrass.debug_binds()'`，
返回 "ok" 但日志不增长 —— 那个函数走 `LOG(Log::DEBUG, …)`，
需要 Hyprland 以 `-v` 启动才可见。所以别指望它。）

## 5. `hl.plugin` 表总是存在，但 `hl.plugin.<名字>` 不一定

写守卫的时候容易写错：

```lua
if hl.plugin == nil then return end          -- ✗ 永远不成立
if hl.plugin.hyprgrass == nil then return end -- ✓
```

`hl.plugin` 这个表即使一个插件都没装也存在，所以要判的是具体插件的键。

## 6. fcitx5 的 PATH 里没有 ~/.local/bin

`fcitx-virtualkeyboard-adapter` 用 `system()` 执行命令，PATH 继承自 fcitx5 进程：

```
/usr/local/sbin:/usr/local/bin:/usr/bin:/usr/bin/site_perl:…
```

**没有 `~/.local/bin`。** 所以配置里必须写绝对路径，否则静默失败 ——
没有报错，键盘就是不弹，很难往 PATH 上想。

验证方法：

```bash
env -i PATH=/usr/local/sbin:/usr/local/bin:/usr/bin /bin/sh -c "wvkbd-toggle show"
# 报 command not found 就对了
env -i PATH=/usr/local/sbin:/usr/local/bin:/usr/bin /bin/sh -c "/home/charlen/.local/bin/wvkbd-toggle show"
# 这条应该生效
```

## 7. wvkbd --auto 和 fcitx5 抢同一个协议

`zwp_input_method_manager_v2` 只能有一个绑定者。fcitx5 作为输入法占着它，
`wvkbd --auto` 也想绑，于是互斥。squeekboard 同理。

解法见 `docs/03-虚拟键盘.md`：不用 `--auto`，改由 fcitx5 侧通知。

## 9. iio-hyprland 是普通用户进程，但传感器在系统 D-Bus 上

直接 `hl.exec_cmd("iio-hyprland")` 能用，但**开机偶发不旋转** ——
因为 `iio-sensor-proxy` 还没就绪。这种偶发最难查（重启一次就好了）。

用 systemd user unit 声明 `Wants=iio-sensor-proxy.service` 让 systemd 保证顺序。
注意 `iio-sensor-proxy.service` 是 `static`（没有 `[Install]`），
所以用 `Wants=` 而不是 `Requires=` —— 它由 D-Bus 激活，
`Requires=` 会让本 unit 在它没被激活时直接失败。

## 11. 刷视频机身发烫：UHD 620 不能硬解 AV1

**现象**：只开 Firefox 和 v2rayN，刷一会儿视频机身就烫手。

**不是代理的锅。** 2026-09-27 实测，sing-box + v2rayN 开了 1.6 小时，合计 CPU 时间约 2 分钟。
真正的大头是 Firefox，开了 10.5 分钟用掉约 18 分钟 CPU（平均占 1.7 个核）：

| 进程 | CPU 时间 | 说明 |
|---|---|---|
| Isolated Web Content | 6:28 | 网页内容 |
| firefox 主进程 | 5:58 | 界面、合成 |
| **RDD Process** | **5:24** | **专门解码视频的进程** |

RDD 占这么多 CPU = 在用 CPU 软解。它的 `/proc/<pid>/maps` 里加载了 `libdav1d`（软件 AV1 解码库）。
i5-8250U 的 UHD 620 只能硬解 H.264 / HEVC / VP9 / VP8，**不支持 AV1**，
而 B站、YouTube 默认大多推 AV1。本机没有风扇，软解几分钟机身就烫了。

**解法**：在 Firefox 里关掉 AV1，网站会改推 VP9 / H.264，交给 VA-API 硬解（`intel-media-driver`）。
本机 `~/.config/mozilla/firefox/ih46znl2.default-release/user.js` 已加：

```js
user_pref("media.av1.enabled", false);
user_pref("media.ffmpeg.vaapi.enabled", true);   // 新版默认已开，写上防被重置
```

重启 Firefox 生效。

**验证**：

- `about:support` → Media → Codec Support：H.264 / VP9 / VP8 / HEVC 的 Hardware Decoding 显示 Supported；
  AV1 那行 Software Decoding 仍显示 Supported **是正常的** —— 这张表只列 Firefox 自带的解码器，
  跟网站能不能拿到 AV1 无关
- 控制台里 `MediaSource.isTypeSupported('video/mp4; codecs="av01.0.05M.08"')` 返回 `false`
- 放视频时 `top -p $(pgrep -f "RDD Process")` 只有个位数
- YouTube 右键「详细统计信息」，codecs 是 `vp09` / `avc1`，不是 `av01`

**注意**：

- `user.js` **不在 `manifest.map` 里**（配置目录名 `ih46znl2` 是随机生成的）。
  重装系统或新建 Firefox 配置后要手动补这两行，连同 `docs/06` 里的
  `ui.key.menuAccessKeyFocuses`。
- 如果某个网站只提供 AV1、放不出来，删掉 `media.av1.enabled` 那一行再重启即可恢复。

**顺带发现的常驻负载**：触屏内核线程 `ipts_poll` 一直在轮询，开机 2 小时用了约 9 分钟 CPU
（≈ 一个核的 7%），所以桌面闲着时 load 也在 3 上下。这是 IPTS 驱动的工作方式，
要么接受，要么不用触屏时停掉 `iptsd`。本机主要当平板用，所以不处理。
