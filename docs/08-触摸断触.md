# 08 · 触摸断触（本次排查全过程）

## 结论摘要

**触屏"不灵敏"不是驱动或配置问题，是 iptsd 在手指快速移动时反复丢失接触点。**

一次连贯的滑动会被拆成很多个 8-60ms 的小片段（`DOWN` → 几毫秒 → `UP` → 再 `DOWN`）。
上层每收到一次 `UP` 就当作一次独立操作，所以：

- 滑动不跟手、拖拽中断
- 长按失效（按住过程中被判定为抬手）
- **手势被误触发** —— 这是最烦人的后果，见下面「画板为什么会弹走」

## 实测数据

用 `libinput debug-events` 记录触摸节点（`event30`），统计每次接触的时长：

| 测试 | 应有接触次数 | 实际接触次数 | 单次时长 |
|---|---|---|---|
| 慢速横划（第一次） | 1 | **1**（7.74 秒，447 个点） | 正常 |
| 慢速横划（尾段） | 1 | **9 个碎片** | 51-272ms |
| 快速横划 | 1 | **16 个碎片** | 8-30ms |
| 三指按住 5 秒 | 3 | 47 个碎片 | 多数 <40ms |
| 单指按住不动 | 1 | **1**（5.82 秒） | 正常 |

**规律：按住不动 → 稳定；快速移动 → 碎裂。**
三指按住也稳定（回放确认 3.4 秒连续），所以不是多指识别的问题。

## 排除了哪些原因

1. **充电器干扰** —— 排除。插电与电池各测一轮，断触程度一样。
2. **触摸帧数据被清零** —— 排除。逐帧统计热力图亮度：
   无接触帧平均 75.4，有接触帧平均 75.2，**没有变暗**。
   （上游 issue #40 的典型症状是"整帧像素变 0"，你这里不是。）
3. **驱动没装 / iptsd 没跑** —— 排除。内核模块、`iptsd@dev-hidraw1`、
   设备节点、Hyprland 设备绑定全部正常。
4. **触摸被上报两次** —— 已修（见 docs/07 坑 A）。

## 排除了哪些"改参数"的路

上游作者 StollD 在 [iptsd#142](https://github.com/linux-surface/iptsd/issues/142) 里明确说过：

> `Neutral = mode` 是正确的运作方式，除非你 100% 确定自己在做什么，
> 否则不要改 `Neutral` 选项。

原因是：**改 `Neutral` 本身就会造成"双触"和"抬手多出一次触摸"** ——
正是我们想修的症状。所以这条路是反向的。

社区在 SP4/SP5/SP6/SP7/SP8 上验证过的推荐值是：

```ini
[Contacts]
ActivationThreshold = 24
DeactivationThreshold = 20
OrientationThresholdMax = 5
```

**这三项就是当前的默认值，本来就没改过。** 所以调参在这台机器上没有收益。

作者对整类问题的定性（同一条 issue）：

> 你触发的这种不稳定是边缘情况。**它无法被修复**，因为"有接触"和"无接触"
> 之间必须有一条界线。你唯一能做的就是把这条界线挪一挪，让它不影响正常使用。

以及 [iptsd#89](https://github.com/linux-surface/iptsd/issues/89)：

> iptsd 没有 Windows 驱动具备的任何噪声抑制和校准。

## 根因定位到哪一步

排除掉"整帧清零"之后，剩下的机制是：**接触点被判定为不可信而丢弃**。

看 iptsd-plot 回放的三指按住画面（`frames 2842-3187`）：接触点被正确识别，
但编号是 `00`、`01`、`04` —— **`02`/`03` 号接触点被创建过又消失了**。
即便手指完全不动，也有接触点被反复创建/销毁。

iptsd 源码里这条路是：每帧的接触点要做**时间一致性校验**，某个接触点
一旦在某帧没通过校验，`track_validity` 就是**不可恢复**的锁存 —— 只能整体
重建。手指快速移动时，热力图团块的峰值在帧间跳动，正好触发这个。

## 还能试的（按代价从低到高）

1. **`iptsd-calibrate`** —— 重新测量手指尺寸。本机是软件包 3.1.0 自带，
   但没有 `iptsd-sensor-reset`（上游那个建议用不了）。
   ⚠️ 需要人按提示操作，没法远程跑。
2. **摸清是否和屏幕贴膜/脏污有关** —— 边缘那列亮斑（右边缘，
   原始值约 75/255，即高于基线 22-24）在 401 帧里帧帧存在。
   阈值 24 时不会变成假触摸，但它占用了动态余量。
3. **接受现状并让上层容错** —— 这正是本次重做手势配置的思路（见下）。

## 画板为什么会"弹走"

**根因：五指下滑被误触发，打开了抽屉工作区（special workspace）。**

抽屉工作区是空的，盖在正常工作区上层 → 屏幕只剩壁纸和一条
"下一项"按钮的残影。它**不会自己消失**，所以看起来像"窗口凭空消失"。

为什么会被误触发：一次普通触摸在断触时被拆成多段，插件把多段触摸
当成多根手指 → 凑够了五指 → 触发手指总数 + 下滑。

**这类"一个滑动被读成多指"是断触的直接后果**，不是配置写错了。

## 本次配置重做的思路

原版手势表按 PC 习惯写，很多动作在平板上误触代价过大。新原则：

1. **只用 tap / longpress**（点击、按住）—— 静止触发，本设备上最可靠。
   滑动类手势全部移除。
2. **不做破坏性动作**：关窗口、移动窗口到别的工作区、切抽屉工作区，
   全部不绑。误触这些的代价（丢工作、窗口找不回、屏幕被空工作区盖住）
   远大于它们带来的便利。
3. **必须有兜底**：新增 `tablet-rescue`（双指长按触发），
   一键切回工作区 1 + 关抽屉 + 复位卡住的滑动偏移。
   纯触摸用户在平板模式下够不着 `SUPER+1`，没有兜底就没法自救。

指头数分配（两个文件之间不能重复，否则谁生效取决于插件内部顺序）：

| 手势 | 动作 | 文件 |
|---|---|---|
| 三指点击 | 启动器 | touch.lua |
| 三指长按 | 拖动窗口 | touch.lua |
| 四指点击 | 全屏 | touch.lua |
| 四指长按 | 控制中心 | touch.lua |
| 五指点击 | 剪贴板 | touch.lua |
| 底部边缘下滑 | 虚拟键盘 | touch.lua |
| **双指长按** | **救援（复位界面）** | touch-tablet.lua |
| 五指长按 | 退出平板模式 | touch-tablet.lua |

## 验证方法

```bash
# 造坏状态
hyprctl dispatch 'hl.dsp.workspace.toggle_special()'
hyprctl dispatch 'hl.dsp.focus({ workspace = "7" })'
# 救援
tablet-rescue
# 应回到工作区 1，且日志在 $XDG_RUNTIME_DIR/tablet-rescue.log
```

实测：从「工作区 7 + 抽屉打开」恢复到「工作区 1 + 窗口正常」。
